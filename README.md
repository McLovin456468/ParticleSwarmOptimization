# Оптимизация размещения камер наблюдения на дискретной карте здания

## 1. Постановка задачи

Разместить `K` камер наблюдения на карте здания так, чтобы:
- покрыть максимальное количество важных точек;
- не размещать камеры в стенах;
- минимизировать пересечение зон обзора (перекрытие).

**Задача используется как учебная дискретная постановка для сравнения методов оптимизации.**

### Поток данных

```
data/map.json → grid, K, R → optimizer → coordinates of K cameras → compute_score → score
```

| Элемент | Описание |
|---------|----------|
| Оптимизируемые переменные | координаты камер `C = [(r₁, c₁), ..., (r_K, c_K)]` |
| Карта и параметры | фиксированы в `data/map.json` |
| Сравнение методов | все методы сравниваются по одной и той же функции `score` |

---

## 2. Входные данные

Основной входной файл — `data/map.json`. Формат человекочитаемый: поле `grid` хранится как список строк.

### Поля файла

| Поле | Значение | Описание |
|------|----------|----------|
| `grid_size` | 100 | размер карты: 100 × 100 клеток |
| `K` | 10 | точное число камер в решении |
| `R` | 12 | радиус обзора камеры (в клетках) |
| `n_walls` | 969 | число клеток-стен |
| `n_points` | 150 | число важных точек |
| `grid` | `list[str]` | карта здания: одна строка JSON на одну строку сетки |

### Семантика клеток

| Значение | Описание |
|----------|----------|
| `0` | свободная клетка (камера может быть размещена) |
| `1` | стена |
| `2` | важная точка (желательно видимая хотя бы одной камерой) |

### Система координат

- Координаты задаются как `(r, c)`, где `r` — индекс строки, `c` — индекс столбца.
- Индексация начинается с нуля.
- Верхний левый угол карты: `(0, 0)`.

## 3. Генерация карты

Карта генерируется модулем `src/map_tools/generator.py`.

**Особенности генерации:**
- Задаются комнаты, дверные проёмы и зоны повышенного интереса.
- Случайность фиксирована (`seed = 42`) — карта воспроизводима.
- 70% важных точек размещаются в `IMPORTANT_AREAS` (верхние кабинеты, переговорная с офисом, серверная).
- 30% важных точек — в остальных свободных клетках.
- Стены и дверные проёмы задаются явно в коде генератора.

**Готовый вход для методов** — `data/map.json`, а не сам генератор.

### Визуализация карты

| Цвет | Значение |
|------|----------|
| Белый | свободные клетки |
| Чёрный | стены |
| Оранжевый | важные точки |

## 4. Стены и линия обзора (LOS)

### Роль стен

| Ограничение | Описание |
|-------------|----------|
| Размещение камеры | камера **не может** стоять в клетке со значением `1` |
| Блокировка обзора | стена **блокирует** обзор (камера не видит сквозь стены) |

### Условия видимости клетки

Камера видит клетку `(r, c)`, если одновременно выполнены:

1. **Евклидово расстояние** от камеры до клетки ≤ `R`
2. **Line of Sight (LOS)** — линия обзора не пересекает стену

### Алгоритм LOS

Функция `has_los` в `src/scoring.py`:
- Между двумя клетками строится дискретизированный отрезок через `np.linspace`
- Сэмплы округляются к индексам сетки
- Проверяется отсутствие стены среди этих клеток

## 5. Целевая функция

Пусть `C = [(r₁, c₁), ..., (r_K, c_K)]` — размещение камер.

Функция **максимизации**:

```
Score(C) = 100 × cov(C) − 20 × overlap(C) − 1000 × invalid(C)
```

### Компоненты

| Компонент | Описание |
|-----------|----------|
| `cov(C)` | число важных точек (`grid == 2`), видимых хотя бы одной камерой |
| `overlap(C)` | число клеток карты, видимых **двумя или более** камерами |
| `invalid(C)` | число камер вне карты или в стене |

**Примечание:** чем больше `score`, тем лучше решение.

Функция `compute_score` в `src/scoring.py` возвращает:
- `score`
- `breakdown`: `cov`, `overlap`, `invalid`

---

## 6. Ограничения решения

| Требование | Статус |
|------------|--------|
| Вернуть ровно `K` координат камер | **обязательно** |
| Все камеры внутри карты | желательно |
| Все камеры на свободных клетках (`0`) | желательно |
| Покрывать много важных точек | желательно |
| Минимизировать пересечение зон обзора | желательно |

**Штраф:** `invalid`-решение оценивается, но штраф `1000` за каждую недопустимую камеру делает его плохим.

## 7. Результат оптимизации

Для одного запуска метода:

| Выход | Описание |
|-------|----------|
| Список из `K` координат камер | `[(r₁, c₁), ..., (r_K, c_K)]` |
| Итоговый `score` | значение целевой функции |
| `breakdown` | `cov`, `overlap`, `invalid` |

**Для честного сравнения:** все методы используют один и тот же `data/map.json` и одну и ту же функцию `compute_score`.

## 8. Методы оптимизации

Методы реализуются отдельно от генерации карты и scoring. Каждый метод ищет координаты камер и оценивается через `compute_score`.

### Genetic Algorithm (GA)

| Характеристика | Описание |
|----------------|----------|
| Тип | популяционный метод |
| Представление решения | список из `K` камер |
| Операторы | отбор лучших решений, crossover, mutation |
| Результат | лучший список камер и `score` |

### Particle Swarm Optimization (PSO)

| Характеристика | Описание |
|----------------|----------|
| Тип | рой частиц |
| Представление | каждая частица хранит кандидатное размещение `K` камер |
| Движение частицы | личный лучший + глобальный лучший решения роя |
| Результат | лучший список камер и `score` |

### LLM as Optimizer

| Характеристика | Описание |
|----------------|----------|
| Тип | языковая модель как оптимизатор |
| Механизм | LLM предлагает новые размещения или улучшает существующие |
| Обратная связь | `compute_score` используется как оценка качества |
| Результат | лучший список камер и `score` |

**Важно:** методы из `scipy.optimize` **не используются** (по требованиям `docs/task_concept.txt`).

## 9. Проверка зазора для оптимизации

Команда: `python -m src.verify`

Сравнение **100 случайных размещений** с **простыми greedy baseline**:

| Метод | Среднее значение | Максимум |
|-------|------------------|----------|
| Random | -2995.60 | 4820 |
| Greedy | 7440 | — |

**Зазор (gap) = 10435.60**

> Поскольку `gap > 5000`, у задачи есть заметный зазор. Даже простая эвристика значительно лучше случайного размещения — методам оптимизации есть что улучшать и сравнивать.

### Greedy baseline

Добавляет камеры по одной, каждый раз максимизируя прирост покрытия важных точек.

## 11. Scope модели

Модель является **учебной дискретной аппроксимацией**.

### Что **не** моделируется

| Аспект | Причина |
|--------|---------|
| Круговой обзор 360° | камеры имеют полный обзор |
| Высота установки | не учитывается |
| Фокусное расстояние | не моделируется |
| Качество изображения | не учитывается |
| Реальные инженерные нормы | выходят за рамки задачи |

**Цель:** задача остаётся понятной, воспроизводимой и удобной для сравнения методов оптимизации.
